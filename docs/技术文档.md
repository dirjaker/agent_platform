# AI Agent 应用平台 — 技术设计文档

> **项目定位**：一个轻量级类 Dify 的 LLM 应用开发平台，支持自定义工具注册、多模型调度、知识库 RAG、DAG 工作流编排和多轮对话。采用单进程 + SQLite 架构，零依赖一键部署。

---

## 一、项目背景与价值

### 1.1 为什么做这个项目？

大模型本身只能生成文本，无法直接操作外部世界。Agent（智能体）的核心能力是**让大模型具备"动手"的能力** —— 通过工具调用（Tool Use / Function Calling）让模型查询数据库、调用 API、执行代码、操作文件系统。

这个项目展示了：
- 对 **Agent 架构** 的深入理解（ReAct、Tool Use、Workflow DAG）
- 对 **大模型能力边界** 的认知（模型擅长推理，工具擅长执行）
- 对 **工程化落地** 的能力（不是玩具 Demo，而是可扩展的平台）
- 对 **类 Dify 平台** 的轻量级实现（单进程 SQLite，无需 Docker/Redis/PostgreSQL）

### 1.2 与 Dify 的对比

| 维度 | Dify | 本项目 |
|------|------|--------|
| 部署 | Docker Compose (PostgreSQL+Redis+Worker) | **单进程** (SQLite，零依赖) |
| 前端 | Next.js + ReactFlow (需 Node 构建) | **Vue3 CDN** (单 HTML，无需构建) |
| 工作流 | 15 种节点，复杂但重 | **6 种核心节点**，够用且轻 |
| RAG | 30+ 向量数据库 | **SQLite + TF-IDF** 内置向量化 |
| 适合 | 企业级多租户 | **个人/小团队**，一台服务器搞定 |

### 1.3 面试话术

> "我做了一个轻量级类 Dify 的 LLM 应用平台，支持自定义工具注册、多模型调度、知识库 RAG、DAG 工作流编排。核心设计是把模型的推理能力和工具的执行能力解耦，通过标准化的工具接口让 Agent 可以灵活扩展能力边界。采用单进程 + SQLite 架构，零依赖一键部署，同时支持真正的流式 SSE 输出和 5 套主题系统。"

### 3.3 工具注册与管理系统

#### 3.3.1 注册机制（tool_registry.py）

使用装饰器模式注册工具，支持自动参数推断：

```python
@registry.register(
    name="http_get",
    description="发送 HTTP GET 请求，返回响应内容",
    category="网络",
    parameters=[
        ToolParameter(name="url", type=ParameterType.STRING, description="请求 URL", required=True),
    ],
    timeout=30,
)
async def http_get(url: str, headers: dict = None) -> dict:
    import httpx
    async with httpx.AsyncClient(timeout=20) as client:
        resp = await client.get(url, headers=headers)
        return {"status": resp.status_code, "data": resp.text[:5000]}
```

核心特性：
- **装饰器注册**：`@registry.register()` 自动注册工具定义和执行函数
- **参数推断**：从函数签名自动推断参数类型和是否必填
- **同步/异步**：自动检测 `async def`，异步执行
- **OpenAI 格式转换**：`to_function_calls()` 转换为标准 Function Calling Schema
- **全局单例**：`registry = ToolRegistry()` 作为全局工具注册中心

#### 3.3.2 工具热加载（tool_loader.py）

启动时自动扫描 `tools/` 目录，动态导入所有 `.py` 文件（以 `_` 开头的除外）：

```python
def load_tools_from_directory(tools_dir: str = None):
    """从目录加载所有工具模块"""
    for py_file in Path(tools_dir).glob("*.py"):
        if py_file.name.startswith("_"):
            continue
        spec = importlib.util.spec_from_file_location(...)
        module = importlib.util.module_from_spec(spec)
        spec.loader.exec_module(module)
```

### 3.4 Agent 核心引擎（agent.py）

#### 3.4.1 ReAct 循环实现

Agent 的核心是一个 **思考-行动-观察（Think-Act-Observe）** 循环：

```
用户输入 → [思考：需要做什么？] → [行动：调用工具] → [观察：工具结果]
     ↑                                                    │
     └────────────── 继续思考或返回最终答案 ←──────────────┘
```

核心流程：
1. 构建消息列表（系统提示 + 历史消息 + 用户输入）
2. 获取可用工具定义（OpenAI Function Calling 格式）
3. 循环调用模型：
   - 如果模型返回 `tool_calls` → 执行工具 → 将结果加入上下文 → 继续循环
   - 如果模型返回文本 → 作为最终答案返回
4. 超过 `max_steps` 步数后自动终止

关键设计：
- **最大步数限制**：防止无限循环（默认 10 步）
- **历史消息管理**：保留最近 20 条消息作为上下文
- **工具调用日志**：记录每次工具调用的参数、结果、耗时
- **自动生成标题**：根据用户第一条消息生成对话标题

#### 3.4.2 流式输出（run_stream）

真正的逐 Token 流式输出，SSE 协议推送：

```
SSE 事件类型:
- token:        逐 Token 文本输出
- tool_call:    工具调用请求
- tool_result:  工具执行结果
- done:         对话完成（含 usage 统计）
- max_steps_reached: 超过最大步数
```

### 3.7 知识库管理器（knowledge_manager.py）

#### 3.7.1 RAG 流程

```
文档上传 → 文本分块 → TF-IDF 向量化 → 存储向量
                                          ↓
用户查询 → 查询向量化 → 余弦相似度检索 → 返回 Top-K 结果
```

#### 3.7.2 文本分块器（TextChunker）

- 按段落分割 → 按大小合并 → 超长段落按句子再分
- 支持重叠（chunk_overlap）保持上下文连贯
- 默认 chunk_size=500，chunk_overlap=50

#### 3.7.3 TF-IDF 向量化器

- 中英文混合分词：英文按单词，中文按字 + bigram
- TF-IDF 计算 + L2 归一化
- 稀疏向量存储（只存非零值，节省空间）
- 序列化/反序列化支持（JSON 格式）

### 3.8 工作流引擎（workflow_engine.py）

#### 3.8.1 DAG 执行流程

```
workflow_config (nodes + edges) → 拓扑排序 → 逐节点执行 → 收集结果
```

核心特性：
- **拓扑排序**：BFS 算法，检测循环依赖
- **变量插值**：`{{node_id.field}}` 语法，引用上游节点输出
- **6 种节点执行器**：
  1. **LLM** — 调用大模型
  2. **Code** — 安全执行 Python 代码
  3. **IfElse** — 条件分支（contains/equals/greater_than 等 10 种操作符）
  4. **HTTP** — 发送 HTTP 请求（GET/POST/PUT/DELETE）
  5. **Tool** — 调用已注册的工具
  6. **KnowledgeRetrieval** — 从知识库检索内容

## 四、自定义工具开发

### 4.1 创建工具文件

在 `tools/` 目录下创建 `.py` 文件，使用 `@registry.register` 装饰器：

```python
from tool_registry import registry
from models import ToolParameter, ParameterType

@registry.register(
    name="my_tool",
    description="工具描述（模型通过这个理解工具用途）",
    category="自定义",
    parameters=[
        ToolParameter(
            name="input",
            type=ParameterType.STRING,
            description="参数说明",
            required=True,
        ),
    ],
)
def my_tool(input: str) -> str:
    """工具实现"""
    return f"结果: {input}"
```

### 4.2 支持异步

```python
@registry.register(name="async_tool", description="异步工具", category="网络")
async def async_tool(url: str) -> str:
    import httpx
    async with httpx.AsyncClient() as client:
        resp = await client.get(url)
        return resp.text[:500]
```

### 4.3 工具自动加载

启动时自动加载 `tools/` 目录下所有 `.py` 文件（以 `_` 开头的除外）。无需手动注册。

## 五、技术亮点总结

1. **ReAct 循环引擎**：完整的 Think-Act-Observe 循环，支持多步骤自主推理
2. **真正流式输出**：逐 Token SSE 推送，包含工具调用状态实时反馈
3. **多模型路由**：自动模型发现 + 故障转移，支持 DeepSeek/OpenRouter/本地模型
4. **工具热加载**：装饰器注册 + 目录扫描，运行时动态添加工具
5. **知识库 RAG**：TF-IDF 向量化 + 余弦相似度，支持跨库语义搜索
6. **DAG 工作流**：拓扑排序 + 变量插值，支持 6 种节点类型的复杂流程编排
7. **单进程架构**：SQLite + 内嵌前端，零依赖一键部署
8. **安全沙箱**：代码执行工具限制危险操作（import、os、subprocess 等）
9. **5 套主题**：CSS 变量实现，支持实时切换
