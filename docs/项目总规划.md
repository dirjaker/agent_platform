# Agent Platform — 类 Dify 完整规划

## 一、项目定位

在现有 `agent_platform`（Function Calling + ReAct + 工具注册）基础上，扩展为一个**轻量级 LLM 应用开发平台**，类似 Dify 但更轻量、更适合个人/小团队使用。

### 核心差异（vs Dify）
| 维度 | Dify | 我们的方案 |
|------|------|-----------|
| 部署 | Docker Compose (PostgreSQL+Redis+Worker) | **单进程** (SQLite，零依赖) |
| 前端 | Next.js + ReactFlow (需Node构建) | **Vue3 CDN** (单HTML，无需构建) |
| 工作流 | 15种节点，复杂但重 | **8种核心节点**，够用且轻 |
| RAG | 30+向量数据库 | **SQLite + 内置嵌入**（sentence-transformers） |
| 适合 | 企业级多租户 | **个人/小团队**，一台服务器搞定 |

## 二、功能模块总览

### 模块1：应用管理（Bot）
- 创建/编辑/删除应用
- 应用类型：聊天助手、工作流、文本生成
- 每个应用独立配置：系统提示词、模型、工具、知识库
- 应用发布为API（生成API Key）

### 模块2：可视化工作流编排
- 拖拽式DAG画布（基于drawflow或自研SVG）
- 8种核心节点：
  1. **开始** — 用户输入/触发器
  2. **结束** — 输出结果
  3. **LLM** — 调用大模型，支持Prompt模板
  4. **知识检索** — 从知识库检索相关内容
  5. **代码执行** — 运行Python/JS代码
  6. **条件分支** — IF/ELSE判断
  7. **HTTP请求** — 调用外部API
  8. **工具** — 调用已注册的工具
- 节点间变量传递（`{{node_id.output}}`语法）
- 工作流保存/加载/导出(JSON)
- 执行日志和调试

### 模块3：知识库（RAG）
- 文档上传（TXT/MD/PDF/Word）
- 文本分块（按段落/按字数/按句子）
- 向量嵌入（sentence-transformers本地模型）
- 语义检索（余弦相似度）
- 知识库管理（增删改查）
- 关联到应用

### 模块4：对话Playground
- 流式输出（SSE）
- Markdown渲染 + 代码高亮
- 对话历史管理
- Token统计和耗时显示
- 调试信息（工具调用链、检索结果）

### 模块5：模型管理
- 多Provider支持（DeepSeek、Ollama）
- API Key配置
- 模型列表和测试
- 用量统计

### 模块6：工具市场
- 内置工具列表
- 自定义工具注册（API描述 → 自动生成工具）
- 工具测试界面
- 工具分类和搜索

### 模块7：API接入
- RESTful API（给外部系统调用）
- API Key认证
- 对话API（流式/非流式）
- 工作流执行API

## 三、数据库设计

```sql
-- 应用
CREATE TABLE apps (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    app_type TEXT DEFAULT 'chat',  -- chat/workflow/text_generator
    description TEXT DEFAULT '',
    config TEXT DEFAULT '{}',      -- 系统提示词、模型、温度等
    workflow_json TEXT DEFAULT '{}', -- 工作流定义（JSON）
    status TEXT DEFAULT 'draft',    -- draft/published
    api_key TEXT DEFAULT '',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 对话
CREATE TABLE conversations (
    id TEXT PRIMARY KEY,
    app_id TEXT NOT NULL,
    title TEXT DEFAULT '',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 消息
CREATE TABLE messages (
    id TEXT PRIMARY KEY,
    conversation_id TEXT NOT NULL,
    role TEXT NOT NULL,             -- user/assistant/system
    content TEXT DEFAULT '',
    metadata TEXT DEFAULT '{}',     -- token数、耗时、工具调用等
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 知识库
CREATE TABLE datasets (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT DEFAULT '',
    embedding_model TEXT DEFAULT 'local',
    chunk_size INTEGER DEFAULT 500,
    chunk_overlap INTEGER DEFAULT 50,
    doc_count INTEGER DEFAULT 0,
    segment_count INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 文档
CREATE TABLE documents (
    id TEXT PRIMARY KEY,
    dataset_id TEXT NOT NULL,
    name TEXT NOT NULL,
    content TEXT DEFAULT '',
    word_count INTEGER DEFAULT 0,
    segment_count INTEGER DEFAULT 0,
    status TEXT DEFAULT 'pending',  -- pending/processing/completed/failed
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 文档分块
CREATE TABLE segments (
    id TEXT PRIMARY KEY,
    document_id TEXT NOT NULL,
    dataset_id TEXT NOT NULL,
    content TEXT NOT NULL,
    embedding TEXT DEFAULT '',      -- JSON数组，向量
    word_count INTEGER DEFAULT 0,
    hit_count INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 工具
CREATE TABLE tools (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    label TEXT NOT NULL,
    description TEXT DEFAULT '',
    tool_type TEXT DEFAULT 'builtin', -- builtin/custom/api
    parameters TEXT DEFAULT '{}',     -- JSON Schema
    config TEXT DEFAULT '{}',
    enabled INTEGER DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 工作流执行日志
CREATE TABLE workflow_runs (
    id TEXT PRIMARY KEY,
    app_id TEXT NOT NULL,
    status TEXT DEFAULT 'running',  -- running/succeeded/failed
    inputs TEXT DEFAULT '{}',
    outputs TEXT DEFAULT '{}',
    node_runs TEXT DEFAULT '[]',    -- 每个节点的执行记录
    elapsed_ms INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 应用-知识库关联
CREATE TABLE app_datasets (
    app_id TEXT NOT NULL,
    dataset_id TEXT NOT NULL,
    PRIMARY KEY (app_id, dataset_id)
);

-- 模型配置
CREATE TABLE model_providers (
    id TEXT PRIMARY KEY,
    provider_name TEXT NOT NULL,    -- deepseek/ollama
    api_key TEXT DEFAULT '',
    base_url TEXT DEFAULT '',
    models TEXT DEFAULT '[]',       -- 可用模型列表
    is_default INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 四、工作流节点详细设计

### 节点1：开始（Start）
- 输入：用户输入文本 + 可选表单字段
- 输出：`{{start.input}}`
- 配置：输入变量定义（name, type, required）

### 节点2：结束（End）
- 输入：任意变量
- 输出：最终结果
- 配置：输出变量映射

### 节点3：LLM
- 输入：Prompt模板 + 变量
- 输出：`{{node_id.text}}`
- 配置：
  - 模型选择
  - System Prompt（支持变量）
  - User Prompt（支持变量）
  - Temperature
  - Max Tokens
  - 是否流式

### 节点4：知识检索（Knowledge Retrieval）
- 输入：查询文本
- 输出：`{{node_id.result}}`（检索到的文本块列表）
- 配置：
  - 知识库选择
  - Top K
  - 相似度阈值

### 节点5：代码执行（Code）
- 输入：变量列表
- 输出：`{{node_id.output}}`
- 配置：
  - 语言（Python/JavaScript）
  - 代码内容
  - 输入变量映射
  - 超时时间

### 节点6：条件分支（IF/ELSE）
- 输入：条件变量
- 输出：`true` / `false` 分支
- 配置：
  - 条件表达式（支持 ==, !=, >, <, contains, in 等）

### 节点7：HTTP请求
- 输入：URL变量、Body变量
- 输出：`{{node_id.response}}`
- 配置：
  - URL（支持变量）
  - Method（GET/POST/PUT/DELETE）
  - Headers
  - Body模板

### 节点8：工具（Tool）
- 输入：工具参数变量
- 输出：`{{node_id.result}}`
- 配置：
  - 工具选择
  - 参数映射

## 五、前端页面设计

### 5个主页面

```
/ (应用列表)
├── 卡片网格展示所有应用
├── 创建新应用按钮
├── 按类型筛选
└── 搜索

├── 模型配置
├── 工具绑定

├── 对话历史列表
├── 调试信息面板

├── 节点配置（右侧属性面板）
├── 运行/调试按钮
└── 执行日志

/knowledge (知识库管理)
├── 知识库列表
├── 文档管理
├── 分块预览
└── 检索测试

/settings (设置)
├── 模型配置
├── 工具管理
└── 系统设置
```
